# 04 — 하드웨어 배포 (Phase 4)

담당 범위: 훈련된 파라미터 → 실행 가능한 회로 → IBM Nighthawk 실행 → 결과 해석.
**아직 착수하지 않았습니다.** 실제 하드웨어에 아무것도 보낸 적이 없습니다.

## 지금 있는 것

`scripts/01_build_hw_circuits.py` 가 훈련된 파라미터에서 QASM2 회로를 만듭니다.
`--repeats`, `--basis X` 를 받고, 깊이 압축 표를 출력합니다. `results/4x4/hw_circuits.json`
가 T1 재실행에서 생성되었습니다.

이 스크립트는 예전에 두 군데가 깨져 있었습니다 (`optimized_params` KeyError,
Qiskit 1.0에서 사라진 `qc.qasm()`). 하드웨어 배포를 한 적이 없어서 드러나지
않았던 것이고, 지금은 고쳐졌지만 **실제 백엔드에 대해서는 여전히 미검증**입니다.

## 오차 예산

`생존 = exp(-n_2Q × 3e-3)` 기준 (자세한 표는 `01-scale-plan.md`):

- 10×10, T=8.0 → 2Q 게이트 8640개, 생존 5.5e-12. **불가능**
- 10×10, T=0.5 → 2Q 게이트 540개, 생존 0.20. 가능
- 4×4, T=8.0 → 2Q 게이트 1152개, 생존 3.2e-2. 매우 어려움

이 지표는 전역 fidelity의 조잡한 하한입니다. 우리가 재는 국소 관측량과 에너지는
훨씬 천천히 감쇠하므로 실제 여유는 더 큽니다 — 다만 **얼마나 더 큰지를 아직
정량화하지 않았습니다**. 이게 배포 계획의 첫 번째 미지수입니다.

## 착수 전에 정해야 할 것

- Nighthawk 의 실제 연결성 · 오차율로 위 예산을 다시 계산. 지금 숫자는 균일한
  3e-3 가정입니다
- 트랜스파일 후 2Q 게이트 수 (SWAP 오버헤드). 4×4는 격자가 하드웨어에 잘 맞지만
  10×10은 확인이 필요합니다
- 오차 완화: ZNE? 측정 오차 완화? 아무것도 안 함?
- 샷 수와 관측량당 통계 오차. 국소 관측량 4e-3 를 재려면 샷이 얼마나 필요한지
- 목표 2(샘플링)에서 하드웨어 결과를 무엇과 비교할지

## 열린 질문

- 실행 시간과 큐 대기를 포함한 현실적인 일정
- 4×4를 먼저 하드웨어에서 돌려 파이프라인 전체를 검증할 것인가. ED 참값이
  있으므로 배포 경로 자체의 버그를 잡을 유일한 기회입니다. **아마 그래야 합니다.**
