# 이슈별 작업 파일

한 세션에서 모든 주제를 다루면 문맥이 뒤섞이고, 압축이 일어날 때마다 이미
정한 것을 다시 논의하게 됩니다. 그래서 주제를 파일로 갈라 두고 **세션 하나가
파일 하나를 담당**합니다.

## 먼저 읽을 것

| | |
|:--|:--|
| **[../status_4x4.md](../status_4x4.md)** | **4×4 에서 세 목표를 얼마나 이뤘나 — 숫자는 전부 여기서** |
| [../RUNBOOK.md](../RUNBOOK.md) | 데스크탑에서 지금 돌릴 것 |
| [../benchmark_plan.md](../benchmark_plan.md) | 전체 논지와 단계 구성 |
| [../manual.md](../manual.md) | 코드·설정 레퍼런스 |

## 쓰는 법

1. 작업할 주제의 파일을 고릅니다.
2. 그 주제 전용 세션을 새로 엽니다 (프로젝트 폴더에서 `claude` 실행).
   `CLAUDE.md` 는 자동으로 읽히므로 프로젝트 배경은 설명할 필요가 없습니다.
3. 첫 메시지로 담당 파일만 지정합니다. 예:
   > `docs/issues/03-engine-performance.md` 를 읽고, 7×7 비트패킹 엔진을 설계해줘.
4. 세션을 끝낼 때 **그 파일의 "상태 / 결정 / 열린 질문" 을 갱신**하고 커밋합니다.
   이게 다음 세션의 시작점입니다.

노트북과 데스크탑이 문맥을 공유하는 수단은 세션이 아니라 **이 파일들과 git**
입니다. 세션 기록은 기계 밖으로 나가지 않습니다.
