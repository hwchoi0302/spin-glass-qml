>
> **막고 있던 결함 두 개는 코드로 고쳐졌습니다** (`f042a77`, `6b315f9`):
>
> 1. **파일 충돌.** stage 3 이 층수와 무관하게 `trained_params.json` 하나에
>    쓰던 것을 `config.params_path()` 로 바꿔 `te_trained_params_L{n}.json`
>    으로 갈랐습니다. 읽는 쪽은 `config.resolve_params_path()` 를 거치고,

>    없는 폴백이면 `L=9` 를 요청한 호출자에게 `L=3` 레코드를 넘기게 됩니다.
>    `03g_state_averaged.py` 는 파일명·층수 하드코딩을 버리고 결과 디렉터리를
>    **스캔**해 층수를 레코드에서 읽습니다. "6층 회로의 앞 3층을 `L=3` 이라고
>    조용히 보고" 하던 경로가 사라졌습니다.
> 2. **게이트 정합 상대 없음.** grouped-S2 스텝 목록을 손으로 넓히는 대신
>    채점 중인 블록에서 `steps = L*k` 로 **유도**합니다. `L=5` 의 120·240·480
>    2Q 와 `L=6` 의 576 2Q 가 채워졌습니다.

**실측 예산 (2026-09-03, 정렬배열 엔진).** 세 개를 동시에 돌려 벽시계
`L=4` 53 분 / `L=5` 81 분 / `L=6` 95 분. 문서에 남아 있던 "~7 시간" 과
"1에폭을 재서 곱하라" 는 지침은 **둘 다 쓰지 마세요.** 1에폭은 `delta=1e-3`,
warm-start 각도에서 1.2 초로 끝나는데 훈련의 실제 구간(`delta=1e-6`, 훈련된
각도)은 관측량당 7만 항이고 gradient 1회가 문자열 엔진 기준 124 초입니다.
**100배가 넘게 다르므로 1에폭 측정은 예산이 되지 못합니다.**

이 실행이 하루가 아니라 1.6 시간으로 끝난 이유는 훈련이 **정렬배열 엔진**으로
옮겨갔기 때문입니다 (`5babcf7`, `truncation.engine: sorted`). 실제 workload
(X_5, 프로덕션 `L=3` 각도, `delta=1e-6`, 396,896 항)에서 forward 14.6배 ·
**backward 20.3배** · 합계 18.2배이고, 훈련 스텝으로는 15.9배입니다.
**숫자는 바뀌지 않습니다** — 이번 실행의 에폭별 손실이 이전 문자열 엔진
실행과 소수점까지 동일했습니다 (`L=4` 0.063130 → 0.028341 → 0.014064 →
0.007426 → 0.005171).

절단은 `min_delta: 1e-7` 기본값 그대로 둡니다. **`final_delta` 와 `eps_trunc`
를 결과에 반드시 남기세요** — 깊은 층에서 절단이 처음으로 문제가 될 수 있고,
그때 구분할 근거가 그것뿐입니다.

**채점**은 `|0…0⟩` 이 아니라 **곱상태 평균**으로 합니다 (주장 문구가 "임의
곱상태"이고, `|0…0⟩` 단독 채점은 한때 틀린 결론을 만들었습니다 — 2026-09-03
에 또 한 번 그랬습니다, 아래 참고):

```bash
python scripts/03g_state_averaged.py --n-states 24 --T 0.5
python scripts/03g_state_averaged.py --n-states 24 --T 1.0 --out results/4x4/state_averaged_T1.0.json
python scripts/03g_state_averaged.py --n-states 24 --T 2.0 --out results/4x4/state_averaged_T2.0.json
```

새 결과 파일을 스크립트의 파일 목록(`main()` 안 `for fname, L in (...)`)에
추가한 뒤 돌리세요. 세 `T` 전부 돌려야 `report_depth_fidelity.png` 의 세 패널이
갱신됩니다 (그 다음 `python scripts/plot_report_4x4.py`).

> **`--T` 는 2026-09-03 에 고쳤습니다.** 이전에는 옵션은 있었지만 BP-PPS 블록을
> 항상 **한 번만** 적용해서, `T=1.0` 에서 반쪽 시간 회로를 전체 시간 타겟에
> 채점했습니다. 이제 `k = T/0.5` 를 세어 합성합니다. `T=0.5` 결과는 불변입니다.

> **`L=2`·`L=3` 의 세 시각 곱상태 평균은 이미 measured 이고 커밋돼 있습니다**
> (`state_averaged.json`, `state_averaged_T1.0.json`, `state_averaged_T2.0.json`).
> 새로 훈련한 `L=4,5,6` 만 추가하면 됩니다.

**결과 — 목표 ① 성립.** 우위가 세 시각 **모두**에서 `L` 과 함께 단조
증가합니다 (아래 판정 기준의 첫 번째 갈래). 같은 2Q 의 grouped S2 대비
곱상태 평균 infidelity 비:

| `L` | 2Q (`T`=0.5) | `T`=0.5 | `T`=1.0 | `T`=2.0 |
|:--|--:|--:|--:|--:|
| 2 | 48 | **0.50배 (패 1.98배)** | 0.26배 (패 3.90배) | 0.27배 (패 3.72배) |
| 3 | 72 | 2.86배 | 1.23배 | 1.20배 |
| 4 | 96 | 4.16배 | 1.72배 | 1.64배 |
| 5 | 120 | 5.09배 | 2.13배 | 2.05배 |
| 6 | 144 | **5.56배** | **2.28배** | **2.17배** |

전체 숫자는 `results/4x4/goal1_advantage.json`, 그림은
`plots/report_depth_fidelity.png`.

**같이 적어야 하는 단서 넷:**

1. **증가가 감속합니다.** `T`=0.5 의 증분이 +2.36 → +1.30 → +0.93 → +0.47 로
   줄어듭니다. `L`=6 근처에서 6배 부근의 고원에 접근하는 모양이고, "깊이를
   더 주면 계속 벌어진다" 는 문장은 이 데이터가 지지하지 않습니다.
2. **`L`=5·`L`=6 은 수렴하지 않았습니다.** L-BFGS-B 가 `max_iter=200` 상한에
   걸려 멈췄습니다 (`STOP: TOTAL NO. OF ITERATIONS REACHED LIMIT`). `L`=4 만
   144 iteration 에서 `CONVERGENCE` 로 끝났습니다. 그래서 그 두 점의 우위는
   **하한**입니다.
3. **`L`=3 은 더 느슨한 절단으로 훈련됐습니다.** 프로덕션 `L`=3 의
   `final_delta` 는 `1e-5` 인데 `L`=4·5·6 은 `1e-6` 까지 조여졌습니다
   (셋 다 `min_delta: 1e-7` 에는 못 닿음, `eps_trunc` 2.21e-3 / 2.34e-3 /
   2.41e-3). `L`=3 이 상대적으로 덜 훈련된 쪽이므로 위 표의 `L` 추세는
   그만큼 **과장된 방향**입니다.
4. **`S4` 는 게이트를 더 쓰면 결국 앞섭니다.** `T`=0.5 에서 BP-PPS 점이
   존재하는 구간(48~144 2Q)은 전부 BP-PPS 가 이깁니다 — 그 구간의 유일한
   `S4` 점인 120 2Q 는 3.86e-3 로 `L`=5 의 6.23e-5 에 62배 집니다. 그러나
   240 2Q 의 `S4` 가 3.89e-6 이라 `L`=6 의 144 2Q 2.74e-5 보다 아래입니다.
   우위는 **얕은 회로 구간의 주장**이지 모든 깊이에 대한 주장이 아닙니다.

**판정 기준 (원문 유지):**

- 배수가 `L` 과 함께 **커지면** → 목표 ① 성립, 논문에 실을 곡선 ← **이것**
- `L=3` 에서 정점 찍고 **작아지면** → 우위는 특정 깊이의 우연
- `L=4` 부터 지면 → 4×4 에서 목표 ①은 성립하지 않음

### 2-2. (1b) VQE 4×4 — 목표 ③ 경쟁자 표 완성 ✅ 완료

```bash
python scripts/03f_gs_competitors.py --lattice 4 --max-seconds 90
```

**이 실행은 VQE만 채우는 게 아닙니다.** `gs_adiabatic.json` 의 단열 곡선은
`M=32`(768 2Q)에서 끝나는데, **그게 목표 ③ 대표 문장이 인용하는 바로 그
점**입니다 — 안쪽 점이 아니라 곡선의 끝입니다. `03f_gs_competitors.py` 는
`M=100`(2400 2Q)까지 스윕하므로 이 실행이 그 너머를 처음 보여 줍니다.
"단열을 더 깊게 하면?" 은 리뷰어의 첫 질문이고, 답하는 비용은 6분입니다
(단열 파트는 최적화가 아니라 고정 각도 스캔이라 gradient 가 없습니다).

`results/4x4/gs_competitors.json` 은 **아직 한 번도 만들어진 적이 없습니다.**
목표 ③이 "경쟁 회로 곡선이 없다"로 막혀 있는 것의 정체가 이 파일입니다.

⚠️ **`--max-seconds 90` 은 위쪽 층에서 부족합니다.** L-BFGS 는 `maxiter=300`
인데 `L=8` 에서 약 204, `L=10` 에서 164, `L=12` 에서 131 iteration 밖에 못
돕니다(노트북 실측). 즉 **경쟁 회로가 수렴 전에 잘린 채로** JSON 에 들어가고,
그건 우리에게 유리한 방향의 편향입니다 — 경쟁자를 덜 최적화해서 이기는
그림이 됩니다. `--max-seconds 300` 이상으로 돌리고, `L≥8` 결과를 인용할
때는 `maxiter` 에 실제로 닿았는지를 같이 적으세요.

스크립트는 VQE 를 **단열 스케줄로 초기화**한 뒤 무작위 재시작도 함께 씁니다.
무작위 초기화만 쓰면 `p=10` 이 `dE=0.87` 에 갇혀 VQE 를 부당하게 깎게 됩니다
(4×4 에서 실측). 3×3 참고값: VQE `p=10` 이 120 2Q 로 `dE=0.0065`, HVA `L=3`
가 36 2Q 로 `dE=0.0146` → 각도 묶음의 대가가 약 3.3배.

### 2-3. 무질서 메커니즘 — 이제 "값싼 보너스"가 아니라 **차별점**입니다

> **2026-09-03 승격.** 가장 가까운 선행연구(Lin·Gharibyan·Su, *Quantum* 10,
> 2014 (2026), arXiv:2510.02428)가 파울리 경로 전파로 회로를 고전 훈련해
> 100큐비트 이상에서 바닥상태를 준비하고 48큐비트 하드웨어 실행까지
> 했습니다 — 다만 **무질서가 없는 균일 모델만** 다룹니다. "고전 훈련 + 얕은
> 회로" 자체는 더 이상 새롭지 않고, 우리에게 남은 차별점이 무질서입니다.
> 이 스윕이 그 주장을 만드는 실험입니다. 근거: `issues/02-comparison-models.md`.

세 경로의 차이는 구조가 아니라 **회로가 흡수할 수 있는 무질서 정보량**입니다
(층당 자유 각도: 단열 0, VQE 2, HVA 40). 그렇다면 **갭이 작을수록 HVA 우위가
커져야** 합니다 — 단열은 `T_A ~ 1/gap²` 로 불리해지니까요.

```bash
for s in 7 13 21 34 55 89; do
  python scripts/03f_gs_competitors.py --lattice 4 --seed $s --max-seconds 90
done
```

각 결과의 `ed_first_excited - ed_ground_energy` 대비 HVA/단열 배수를 그리세요.
**상관이 보이면 벤치마크 수치가 메커니즘 주장이 됩니다.**

### 2-4. p-VQD 타당성 (착수 전 설계 필요)

`T>0.5` 를 훈련 못 하는 이유는 정답지를 `T` 까지 고전 전파해야 하기 때문입니다.
p-VQD 는 `θ(t) → θ(t+dt)` 를 `max |⟨ψ(θ')|e^{-iH dt}|ψ(θ(t))⟩|²` 로 푸므로
전파할 회로가 `L+1` 층입니다. **항 수가 `T` 가 아니라 안수 깊이에만 의존**하고
비용이 `T` 에 선형입니다. 설계는 `01-scale-plan.md` 의 "돌파구 후보" 절.

### 2-5. "초선형 깊이" 재측정 — 지금은 인용 불가 상태입니다

**우선순위 낮음, 비용 큼. 먼저 1에폭 예산부터 재세요.**

`05-writing.md` 의 음의 결과 "직접 훈련 깊이가 `T` 에 초선형 (2→3→8→도달못함)"
은 `statevector_pilot.json` 의 `time_evolution` 에서 나왔는데, 그건
**`a45a88a` 가 철회한 최적화**입니다 — 각도를 `|0…0⟩` 하나에 맞춘 것이라
`T=0.5`, `L=3` 회로가 `|0…0⟩` 에서 1.4e-5, 곱상태 평균으로는 **0.43** 입니다.

**statevector 라서 부정확한 게 아닙니다.** `2^16` 정확 시뮬레이션이라 계산은
정확합니다. 틀린 건 **잰 대상**입니다 — 한 상태의 궤적을 보간하는 층수이지
`exp(-iHT)` 를 근사하는 층수가 아닙니다.

확인된 것: 임계점 셋(`T`=0.5→`L`=2, 1.0→`L`=3, 2.0→`L`=8)은 전부 **수렴한**
점이라 (85 s / 135 s / 305 s) 시간 예산 문제는 아닙니다. 오직 목적함수 문제.
`T`=4.0 의 "도달못함" 만 `L`=12·16 이 1800 s 에 잘린 것이라 두 문제가 겹칩니다.

**고치려면** `03_statevector_pilot.py` 의 시간진화 목적함수를 `|0…0⟩` fidelity
에서 **곱상태 평균 fidelity** 로 바꿔 각 `(T, L)` 을 다시 최적화해야 합니다.
상태 24개면 gradient 비용이 24배이므로 **먼저 1에폭을 재고 예산을 정하세요.**

**판정:**
- 방향(초선형)이 유지되면 → 음의 결과 그대로 살고, 이번엔 인용 가능한 근거
- 뒤집히면 → 목표 ①의 스케일링 논의가 통째로 바뀝니다
- 못 돌리면 → **"2→3→8" 을 어디에도 쓰지 마세요.** 지금이 그 상태입니다

### 2-6. (1c) CD 단열 기준선 — 목표 ③ 문장이 여기서 결정됩니다

**왜 급한가.** 지금 단열 기준선은 선형 스케줄에 `T_A` 격자 탐색뿐입니다.
문헌의 표준 개선은 counterdiabatic 구동이고 (Hegade et al., *PRApplied* 15,
024038 (2021); DCQO, *PRR* 4, L042030 (2022)), **단일체 변분 CD 항은
`sum_i alpha_i Y_i` 즉 1큐빗 회전**입니다. 우리 통화는 2Q 게이트 수이므로
**이 항은 공짜**입니다. 리뷰어가 "CD 를 붙이면?" 이라고 물었을 때 답이 없으면
15배·25배 문장이 통째로 흔들립니다.

**무엇을 구현하나.** `scripts/03f_gs_competitors.py` 의 단열 경로에 층마다 RY
블록을 추가합니다. 게이트 plan 이 지금 RX/RZZ 만 알므로 `03_statevector_pilot.py`
의 `build_plan` 과 `forward_pass`/`adjoint_grad` 에 `ry` 를 추가하는 것이 먼저입니다
(`apply_ry` 는 `apply_rx` 와 같은 reshape 패턴, 부호만 다름).

두 판본을 다 재세요:

- **(a) 문헌 충실판.** `alpha(s)` 를 단일체 변분식으로 계산해 고정. 자유
  파라미터 없음. "표준 DCQO 를 그대로 붙였다" 라고 쓸 수 있는 판본.
- **(b) 상한판.** `alpha_l` 을 층마다 **자유롭게 두고 최적화**. 2Q 는 여전히
  `24*M` 이므로 이건 "1-local 보조를 최대로 준 단열"의 상한입니다. **이걸
  이겨야 주장이 안전합니다.**

```bash
python scripts/03f_gs_competitors.py --lattice 4 --max-seconds 300 --cd-order 1
python scripts/03f_gs_competitors.py --lattice 4 --max-seconds 300 --cd-free
```

**판정:**

- (b) 를 붙여도 단열이 HVA 곡선 아래로 못 오면 → 목표 ③ 문장이 확정됩니다.
  이때 배수는 (b) 기준으로 다시 계산해 인용하세요.
- (b) 가 배수를 절반 이하로 깎으면 → 대표 문장을 "CD 를 포함한 단열 대비 N배"
  로 다시 쓰고, 2차 CD(`Y_iZ_j`, 2Q 를 쓰므로 같은 비용에서 층수가 줄어듦)까지
  갈지 결정합니다.
- 어느 쪽이든 **결과를 `gs_competitors.json` 에 새 키로 넣고 커밋**하세요.

### 2-7. (1d) 각도 저장 + HVA 깊은 층 재훈련

> **꼬리 RX 층은 하지 않습니다** (사용자 결정 2026-09-03). `|+...+>` 에서
> 1층의 RX 16개는 gradient 가 정확히 0 이라 죽어 있고, 그래서 `p` 층 회로는
> 비용 `p` + 믹서 `p-1` 입니다. RX 는 2Q 를 안 쓰니 꼬리에 한 층 붙이면
> 공짜로 표현력이 커지지만, 세 경로가 똑같이 손해를 보고 있어 편향이 아니고
> 회로 구조를 바꾸면 이미 훈련된 `L=3` 과 비교 기준이 어긋납니다. 기록은
> `issues/02-comparison-models.md` 에 남겼습니다.

1. **각도 저장.** `gs_competitors.json` 은 `n_2q`/`energy`/`fidelity` 만
   남깁니다. 목표 ③의 결과물이 "레지스터 안의 상태"인 이상 경쟁자 회로를
   복원할 수 없다는 건 재현성 구멍입니다. `params` 를 행마다 저장하세요
   (`L=12` 도 480개, 파일 크기 문제 없음). §2-6 의 코드 수정과 같은 파일입니다.
2. **HVA `L=10` (가능하면 `L=12`) 재훈련.** 지금 값은 300초 상한에 걸려
   `L=8` 보다 **나쁘게** 나옵니다 (`dE` 0.049·0.157 대 0.013). 그래서
   `report_goal3_layers.png` 에서 `L>8` 점을 아예 빼 두었습니다 — 그대로 두면
   "안수의 한계" 로 오독됩니다. 제대로 수렴시킨 `L=10` 이 나오면 그림의 HVA
   곡선이 거기까지 이어집니다.

**깊은 행은 300초로도 모자랍니다.** `HVA L>=3`, `VQE p>=8` 이 전부 상한에
걸렸습니다. `gpu_benchmark.json` 파트 B1 이 120초당 163 → 1037 iteration
이므로, 이 재실행은 **GPU 백엔드로 돌리거나 `--max-seconds` 를 1200 이상**으로
주세요.

```bash
python scripts/03f_gs_competitors.py --lattice 4 --max-seconds 1200
```
